# Momcozy Viral Replication Workbench

Buildless, evidence-bound MVP for the project's viral-replication capability graph.

- Entry point: `dist/index.html`
- Deep-insight report: `dist/deep-insight.html` (a source-limited maternal TikTok candidate report plus the `viral-video-deep-insight` skill introduction)
- Product boundary: browser-local workbench plus a curated, owner-private case archive; no raw private asset library, credentials, publishing, billing, ranking, or video-generation integration.
- Case archive: `dist/cases/kleanpal/` and `dist/cases/oumomo/` contain representative videos, keyframes, and redacted JSON summaries; `dist/cases/maternal-tiktok/` contains only an evidence-only case record, Social Resonance Map, and Insight Brief JSON, with no raw social media media. `dist/cases/baby-reaction-diaper-change/` adds a source-limited baby/parenting reaction candidate (ARK record/19758) with metadata-only Social Resonance Map; `dist/cases/nestle-generations-of-love/` adds a separate campaign-awareness benchmark with official Nestlé/TikTok measurement metadata. Neither lane imports original child media, creator assets, audio, connectors or reported lift as Momcozy evidence. The complete local case libraries remain outside the Site package.
- Brand voice case expansion: read `docs/brand-voice-social-case-expansion-spec.md` and `docs/brand-voice-social-case-expansion-tickets.md` before changing the Case Archive. The first baby-social case is an evidence-only, source-limited projection; it has no raw TikTok media.
- Current frontier: `BV-P1-002` is locally verified; `BV-GATE-001` has a local `brand-voice-gate-preflight/v1` record and is `awaiting_user_gate` for case-specific rights, child-safety, connector and external-action evidence. Keep `brand_voice_social` and `campaign_awareness_benchmark` as separate tracks; never rank their views, lift or engagement together.
- Fusion boundary: `inverse_engineer` is represented as an evidence/reverse-engineering adapter and candidate promotion path. Its unfinished Reverse Core, real connectors, media analysis, and Skill Release are not claimed as live capabilities here.
- Capability directory: the site exposes 18 skills and 8 workflow packs. Each skill includes its use case, entry signals, non-goals, inputs/outputs, procedure, completion rule, stop conditions, common misreadings, and handoff; each workflow adds applicable/non-applicable scenarios, primary variable, artifacts, handoff, acceptance, and guardrails.
- Source of truth for the capability model: the repository's `.agents/workflows/viral-replication/` and `docs/product/viral-replication-*.md` documents.
- Deployment checklist: `docs/PLAN.md`
- Humanized copy plan and execution TODO: `docs/humanized-copy-optimization-plan.md`
- Fusion plan and execution TODO: `docs/PLAN.md` (section “融合边界” and the checked/unchecked TODO items).
- Brand voice execution loop: `docs/brand-voice-social-case-expansion-tickets.md` (local ticket frontier; no external tracker is configured).
- Detailed fusion design: `docs/inverse-engineer-fusion-plan.md`.

This directory is intentionally isolated from the existing application worktree so the Site packaging step does not rewrite or publish unrelated project files.
