# 复刻实验结论与阻断门禁

## 结论先行

爆款复刻已完成一条受控基线 `R-B01`：单次提交、扣 25 积分、后续在项目管理中恢复为 `succeeded`，并已导出本地媒体。它证明了“配置→异步队列→持久项目→媒体资产”的技术链路，但不构成可回放矩阵：参考视频稳定性仍未跨会话复验，且成片口播产生了输入图无法支持的性能主张，内容验收为 `fail`。  
因此当前可以做工程链路复刻，不能声称已获得可复现、可商用的爆款复刻能力。  
  
建议优先级仍然是：先完成 `viral-script` 方案的事实-阶段-版本闭环后，再补齐复刻门禁。

## 事实依据（F）

- `Z03` 记录了复刻免费探路的引用可播放性：
  - 有 1 条可播放结果，3 条记录为 `no-player`。
  - 同一参考在刷新后不可重现（`not-reproducible-on-refresh`），触发 `preview instability reached stop condition`。
  - `replica_paid_gate` 为 `false`，未进入付费复刻提交。
- `Z11` 项目页验证中确认已有复刻项目可查看：`projects_total=3`，含 `video-replica` 与 `viral-script`。
- `M-EX01` 对既有复刻产物取证显示：
  - `unsupported_visual_claims: ["invented pouch contents"]`。
  - 口播和文案存在未基于输入约束的编造点，`verdict=fail`。
- `R-B01`：使用一张合成无品牌保温瓶图和 `Mini / 15s / 9:16 / English / 720P / 1` 完成一次受控提交。项目管理后续显示已完成 25、生成中 0、失败 0；余额 `695 → 670`，与 25 分报价一致。导出的本地媒体为 15.104 秒、720×1280、24fps、H.264/AAC。
- `R-B01` 的帧格显示人物、厨房和深灰瓶身跨镜头连贯，然而 ASR 得到“长时间保温、绝不漏、紧密密封、结实”等性能/质量表述。输入仅为无文字的合成商品图，不能支持这些主张，故技术终态 `succeeded` 与内容 verdict=`fail` 必须并存。

## 阻断分析（I-M）

- `replica_paid_gate` 在免费探路中未触发，说明当前证据不足以稳定定义“可复刻基线”。
- 预览态与刷新态不一致，说明任务链路还缺少可复现快照条件（`preview_observable + same_reference + same_prompt + same_input_images` 不成立）。
- `R-B01` 已解除单条“提交、扣费、项目恢复、媒体导出”的链路未知性；但其只有 n=1，且中间状态只保留相对顺序，不能用于估计随机性、时延分布或参考复现率。
- `R-B02 / R-B03 / R-I03 / R-P01 / R-V02` 仍不得在没有重新冻结稳定参考、输入与报价的情况下继续消耗积分。

## 2026-08-12 免费链路复核

- 复刻页的主入口要求粘贴 TikTok/FastMoss 视频链接或搜索视频；在空输入下点击不会进入配置，也不会产生任务或积分变化。
- 榜单首条的“爆款复刻”按钮实际导航到 `video-script`，而不是带参考视频上下文的复刻配置页。
- 因此，榜单当前只能作为趋势发现入口，不能作为可重放的参考视频输入。它没有补齐 `same_reference`、可播放预览或可刷新复现条件，`replica_paid_gate` 继续为 `false`。

## 2026-08-12 R2-P01：配置合同已重现，付费门禁仍未解除

本轮从当前榜单卡片进入了“爆款复刻配置”弹窗，当前会话内能看到参考视频预览、商品图上传区和提交前报价。这修正了“只能跳到脚本页”的过时观察，但仅是一次会话内的正向观察，尚不能代替刷新后的同参考复现。

已冻结的高质 30 秒配置为：`9:16`、英语、`720P`、数量 1、最多 9 张白底商品图、可选提示词上限 2000 字符，报价 180 积分。可见报价矩阵为：高质 10/15/30 秒分别 60/90/180；Mini 15 秒 25；快速 15 秒 60。未上传任何图片、未提交，因此余额保持 695。

这说明复刻产品的最小付费基线应是 `Mini / 15s / 9:16 / English / 720P / 1`，而非高质 30 秒。它以 25 分将首次受控试验的成本降至可接受范围，但仍需同时满足两项门禁：

1. 用户指定一张可发送给 Oumomo 的商品图；不能复用此前仅用于数字人模块的任意图片。
2. 对同一参考完成一次刷新后配置重开，确认参考仍可播放且报价合同不变。

满足后才可提交一次 `R-B01`；该次只允许一次提交，并记录预报价、余额、进度、终态、媒体哈希和事实/包装/镜头评分。若任一门禁失败，停止而不扣分。

## 2026-08-13/14 R-B01：单次提交、终态恢复与媒体质检

在 `Mini / 15s / 9:16 / 英语 / 720P / 1`、单张合成商品图和 25 分报价下，R-B01 只提交一次。前端短暂显示“处理中…”，随后关闭配置弹窗并自动展开任务队列；同一任务在可见队列中依次显示 `10 → 30 → 45 → 60 → 80 → 95%`。

短窗口结束时，队列仍为“进行中 (1)”和 95%，余额仍为 695；这一中间事实保留在状态序列中，不把 95% 当作终态。后续项目管理显示“已完成 25 / 生成中 0 / 生成失败 0”，新近复刻项目可见下载入口，余额变为 670，精确对应 25 分报价。因此终态已由持久项目恢复为 `succeeded`，且没有第二次提交。

浏览器直接点击下载没有触发可捕获的下载事件，属于 UI 导出路径缺陷；页面资产包导出成功，已保存本地 MP4 及 SHA-256、帧格和 ASR 文本。五点抽帧显示人、厨房、杯子和深灰瓶身连续稳定，技术质量合格。输入图没有商品性能事实，ASR 却出现“保温更久、绝不漏、瓶盖很紧、结实”等表述；故该条在“任务完成”和“媒体事实可接受”两个门分别是 `succeeded` 与 `fail`。

## 2026-08-14 R3-P01：配置报价重现，播放门禁仍阻断

同一当前会话的首张榜单卡可再次进入配置弹窗。选择 Mini 后，观察到的提交前合同仍是：`9:16 / 15s / English / 720P / 1`，报价 `25` 积分；商品图为 `0/9`，余额保持 `670`。这只证明当前 UI 的配置与报价可重开，不能证明引用已被冻结为同一条稳定样本。

“原视频预览”位于一个跨域 iframe，顶层页面没有可读取的 video 播放状态；因此无法独立确认 ready、播放进度或可播放性。按照 `replica_paid_gate`，该条件不足以开展新的付费提交。R3-P01 没有上传图片、没有点击生成、没有创建任务，账本增量为零，verdict=`blocked`。

## 价值与复刻判断（综合）

- 价值：★★★★★  
  - 具备高商业价值，但当前实施风险在于引用稳定性、输出可复现性和模型路由不透明度。
- 技术壁垒：★★★★☆  
  - 引用抓取、素材一致性、异步恢复、事实对齐联合约束，复杂度高于预期。
- 实施复杂度：★★★★★  
  - 与 `viral-script` 相比更高，建议在后续第二阶段再放大投入。
