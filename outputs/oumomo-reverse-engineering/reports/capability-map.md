## 最值得复刻的组合

第一优先不是单独复制“生成按钮”，而是“商品事实工作台 + 爆款脚本 + 项目/素材工作区”。它能复用现有 P0 的事实门、版本、异步任务和校验能力，直接解决商品可信、脚本可编辑、结果可追溯、失败可恢复四个高频问题。

第二优先是“多角度白底图 + TK 图文带货”。技术壁垒和单次成本较低，输出又能反哺链接生视频、爆款复刻和商品素材库，投入产出比明显高于先做数字人或模型聚合。

第三优先才是链接生视频。真实付费提交复现了 HTML/JSON 错误，但后台任务继续运行并最终成功；这会制造高风险的重复提交歧义。复刻时必须以可靠导入、事实审核、幂等投递和失败恢复为前置条件。

## 当前网站的关键缺陷

- 输入反馈不一致：脚本空输入和复刻格式错误输入会静默无响应，链接生视频则先进入“正在获取”再失败。
- 报价不统一：脚本、复刻、图文等可见，模板和若干媒体工具必须上传或选片后才显示。
- 参考视频不稳定：同一榜单预览首次可播放，刷新后多条无法建立播放器，付费门禁不能依赖一次成功。
- 工作流跨路由：去重页选择已有复刻项目后跳到图文带货页面，说明项目类型路由或恢复状态存在缺陷。
- 同一跨路由缺陷已在链接生视频项目上对“去重”和“发布前检测”各复现一次；发布页项目选择则保持在原路由，说明缺陷位于两类工具的项目选择回调而非通用素材选择器。
- 商品事实缺少来源状态：页面直接把抓取卖点作为生成输入，没有展示证据来源、确认状态和冲突处理。
- 厂商主张与可验证事实混合：官方接口、去重成功率和权重提升等说法需要独立验证，不能直接作为工程验收口径。
- API/前端错误是系统性的：项目下载、模型页、去重、预检、模板、白底图、标签和增强页均出现 HTML 被当作 JSON 解析；页面“可见”不等于功能链路可用。
- 图片模型输出合同不统一：同一 `1K` 控件产生 GPT 1254×1254 PNG 与 Nano 1024×1024 JPEG；Nano 文件仍以 `.png`/`image/png` 暴露。
- 图片模型没有商品身份门：Nano 一次删除真实底部白线，两次都改变包装比例和版式，任务仍直接标为完成并进入项目库。
