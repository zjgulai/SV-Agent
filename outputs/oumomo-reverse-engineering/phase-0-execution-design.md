# Oumomo 四功能逆向蒸馏执行设计

日期：2026-08-10
范围：爆款榜单与筛选、爆款复刻、链接生视频、爆款脚本生成
当前阶段：执行前设计；尚未进行付费生成、上传或接口级逆向

## 1. 目标与成功定义

目标是通过正常产品流程，蒸馏出可独立实现的行为规格、数据模型、AI 组件候选、状态机、质量标准和失败边界。目标不是复制源码、私有提示词、受保护素材或凭证。

“一次成功”不能定义为第三方 AI 永不失败，而定义为：

1. 付费动作前已经完成所有免费预检；
2. 每个功能只提交一个明确任务，不因页面迟延重复点击；
3. 即使供应商任务失败，也能凭任务 ID、状态、积分变化和日志确定失败位置；
4. 每项结论都可区分为事实、推断或未知；
5. 成功任务的输入、配置、状态、扣费和输出可以一一追溯；
6. 最终规格足以让未参与观察的工程师重放测试并实现行为等价版本。

## 2. 三种执行方式

### 方案 A：公开 UI 与产物分析

只使用页面、可见 DOM、截图、正常交互、任务队列、积分余额和自己生成的产物。安全性最高，但无法确认真实 API 字段、模型供应商或后台状态协议。

### 方案 B：授权后的被动结构观察（推荐）

在方案 A 基础上，被动记录正常 UI 自然触发的网络请求路径、字段名、字段类型、状态码、耗时和响应结构。禁止请求重放、修改、参数枚举、接口批量调用和认证信息记录。

只有用户确认具有站点权利人或项目所有人的书面授权时才启用方案 B；否则自动降级为方案 A。

### 方案 C：直接接口重放、源码或隐藏参数枚举

不采用。它会扩大合规、隐私、重复扣费和账号风险，也不是构建洁净室规格所必需。

## 3. 不可越过的边界

- 不读取或记录 Cookie、Token、Local Storage、Session Storage、密码、手机号、邮箱或账号标识。
- 不导出完整 HAR，不使用 Copy as cURL，不保存带签名查询参数的媒体 URL。
- 不绕过登录、验证码、权限、付费、反爬、速率限制或平台安全控制。
- 不执行 TikTok 发布、账号绑定、收藏、订阅或四个目标功能以外的写操作。
- 不使用真实客户素材；优先使用站内示例和无品牌、非敏感的合成商品图。
- 网络观察只记录业务路径、字段结构和时序；任何敏感字段出现时立即停止正文检查。
- 403、429、验证码或安全拦截出现时立即停止，不换 IP、不连续重试。

## 4. 共同方法论

### 4.1 证据分层

| 标记 | 含义 | 允许的表述 |
|---|---|---|
| F | 当前运行直接观察到的事实 | “页面显示”“请求包含”“任务状态为” |
| I-H | 至少两类事实支持的高置信推断 | “证据支持存在某类组件” |
| I-M | 单一稳定模式支持的中置信推断 | “可能采用” |
| U | 当前不可观察或证据冲突 | “未知，不能确认” |
| Vendor claim | 官方营销或帮助文档声明 | “官方宣称，未独立验证” |

### 4.2 单变量差分

每次只改变一个变量：地区、日期窗、参考视频、商品、语言、受众、风格、模型、时长或清晰度。每轮记录固定项、唯一变化项和输出差异。完全重复输入用于估计随机性，避免把生成波动误认为变量作用。

### 4.3 因果证据链

```text
输入来源
  → 归一化商品/参考对象
  → 卖点与结构证据
  → 脚本
  → 分镜与提示词候选
  → 模型路由与异步任务
  → 后处理
  → 输出产物
  → 积分账本
```

商品事实必须能从源商品追溯到脚本、字幕、口播和画面；参考视频结构必须能追溯到成片的钩子、节奏和镜头角色。

## 5. 统一日志规范

每个动作生成一条事件记录：

```text
experiment_id, case_id, seq, ts_utc, feature
channel: ui | dom | network | state | job | credit | media
route_without_sensitive_query
action, control_label, before_value, after_value
method, path_template, status, latency_ms
request_key_set, response_key_set, request_id_hash, job_id_hash
state, stage, progress, attempt_no, error_class
credit_before, quoted_credit, credit_after, ledger_delta
artifact_role, mime, bytes, width, height, fps, duration, codec, sha256
verdict: pass | fail | blocked | inconclusive
evidence_ref, confidence, redactions, notes
```

统一采集点：

1. 页面进入并稳定；
2. 每次 UI 动作前；
3. 动作后第一个可见状态变化；
4. 请求完成；
5. 任务创建；
6. 每次任务状态变化；
7. 终态；
8. 积分结算；
9. 输出下载与媒体分析。

页面稳定定义为连续 2 秒结果数量、首项指纹和 loading 状态不变化。生成任务按官方指南预留 3–5 分钟基础等待窗，但以任务状态而非固定计时判断结束。

## 6. 公共执行门禁

### Gate 0：范围与授权

- 确认使用方案 A 或方案 B。
- 确认积分硬上限。
- 建立禁止控件列表。

### Gate 1：环境与身份保护

- 只使用当前已登录 Chrome 标签页。
- 记录路由、语言、时区、视口、余额和任务队列是否为空。
- 日志脱敏试录必须为零敏感字段。

### Gate 2：免费探路

- 走到每个功能最后一个付费按钮之前。
- 枚举所有公开配置、校验、报价和错误态。
- 空输入、错误 URL、错误素材必须不创建任务、不扣积分。

### Gate 3：输入夹具冻结

- 榜单使用公开筛选条件。
- 其他功能优先使用站内示例。
- 商品素材使用同一个合成 SKU：固定品名、颜色、规格、三条卖点和三张白底多角度图。
- 对输入文件计算 SHA-256。

### Gate 4：报价与幂等

- 生成按钮前记录配置、实时报价、余额和预计扣费。
- 只点击一次；按钮未反馈时先检查任务队列和网络状态，禁止再次提交。

### Gate 5：任务终态

- 记录唯一任务 ID、状态序列和积分变化。
- UI 显示成功但媒体不可播放，不算成功。
- 失败后先对账，不自动重跑。

### Gate 6：输出验收

- 下载自己生成的产物。
- 记录编码、分辨率、时长、音轨、文件哈希、镜头和字幕。
- 对照商品事实、参考结构和用户配置。

## 7. 功能一：爆款榜单、地区/品类/GMV/销量筛选

### 目标组件

```text
上游数据源
→ 视频/商品/地区/品类身份归一化
→ GMV 与销量窗口聚合
→ 去重与币种处理
→ 爆款评分/排序
→ 物化榜单或搜索索引
→ 查询 API/缓存
→ 筛选与卡片 UI
```

上游来源、GMV 归因和“实时”刷新 SLA 默认保持未知，除非授权观察或官方技术文档提供直接证据。

### 执行步骤

| 步骤 | 动作 | 记录 | 通过条件 |
|---|---|---|---|
| R0 | 以 `US + 7D + 全部` 建立基线 | URL、筛选、前 10 项指纹、排序、卡片字段、时间 | 页面稳定，无积分动作 |
| R1 | 逐个打开地区、品类、GMV、视频类型、日期、销量控件 | 公开枚举、默认值、disabled 状态 | 不靠隐藏参数发现选项 |
| R2 | 每轮只改一个筛选并重置 | URL diff、结果指纹、总数、时间 | UI、URL 与结果同步变化 |
| R3 | 采集 A、B、A+B | 单筛选和组合结果 | 组合结果满足 AND 语义或明确标为未知 |
| R4 | 切换公开排序方向 | 前 10 顺序、数值和 tie | 可见数值与排序方向一致 |
| R5 | 仅翻一页或加载一次更多 | cursor/page、重复项、缺口 | 两页无异常重复 |
| R6 | reload、后退、前进、重置 | URL 与状态恢复 | 状态合同可复现 |
| R7 | T0、T+30m、T+2h、T+24h 重复同一查询 | 指纹、更新时间、缓存元数据 | 只给刷新周期上界，不把营销“实时”当事实 |
| R8 | 最多抽样 40 项做质量检查 | 缺失率、唯一性、非负数值、时间、币种 | 每个质量结论有样本与限制 |

### 最小测试矩阵与成本

12 个只读用例：基线、reload、地区、品类、GMV、类型、7D/14D、排序、组合、分页、重置、空态。积分成本为 0。

### 状态机候选

```text
COLD → CONFIG_LOADING → QUERY_LOADING → READY | EMPTY | ERROR
READY → FILTER_CHANGE → QUERY_LOADING
READY → APPEND_PAGE → READY | END | ERROR
READY/EMPTY/ERROR → RESET → QUERY_LOADING
任意稳定态 → RELOAD/BACK/FORWARD → RESTORING → QUERY_LOADING
```

### 主要失败回退

- 需要登录、验证码、403 或 429：停止。
- 数据动态：以快照时间和指纹解释，降低置信度。
- 只有 K/M 显示值：只报告数值区间，不伪造精确值。
- 第三次语义验证仍冲突：停止局部试验，审查窗口、缓存、Top-K 截断和 URL 状态源。

| 步骤 | 动作 | 记录 | 通过条件 |
|---|---|---|---|

| V7 | 下载成片并做媒体与内容分析 | 编码、帧、ASR、OCR、镜头、哈希 | 可播放且参数匹配 |
| V8 | 只有基线成功后，进行一次完全重复输入 | 输出差异和随机方差 | 不把随机差异当变量效果 |

### 成本

- 官方当前最低公开价：Fast、480P、10 秒，30 积分。
- 基线加一次完全重复：60 积分。
- 页面实时报价不同则停止并重新确认，不扩大预算。

### 2026-08-10 实测回填

- 实际最低档为 Mini/480P/15 秒/1 个，报价并净扣 30 积分；只提交 1 次，没有执行 V8 重复实验。
- V2–V6 已完成：合成商品图上传成功，任务状态经历 `5→45→55→70→80→95→SUCCEEDED`，总耗时约 239 秒，刷新后可在项目管理恢复同一任务。
- V1 只部分通过：站内参考对象存在，但 TikTok iframe 持续不可播放。经用户确认后仍执行了基线任务，因此成片成功不能作为结构复刻成功的证据。
- V7 部分完成：浏览器可播放，元数据 15.104 秒、496×864；三个抽检帧的包装主色、标识和商品名稳定。尚未执行下载、ASR、OCR、编码和逐镜头离线分析。
- 项目页显示五段式生成提示词，证明存在中间 prompt compiler；该层在无商品事实支持时自行加入能量、口味和用量宣称，clean-room 实现必须在编译前绑定 `ProductFact` 证据并在渲染前设置 claim gate。

### 质量门槛

- 钩子出现时间相对参考偏差不超过 0.5 秒。
- 首次商品展示时间偏差不超过 1 秒。
- 结构角色序列 `Hook → Pain → Demo → Proof → CTA` 加权 F1 初始门槛 0.75。
- 不保留参考账号水印、用户名、连续原音频或长段字幕。
- 商品类别、主色、包装、Logo、数量和配件必须正确。
- 结构相似、原创性、商品保真三门必须同时通过。

### 状态机候选

```text
DRAFT → REFERENCE_VALIDATING → REFERENCE_READY
→ ASSET_UPLOADING → ASSETS_READY → ANALYZING
→ CONFIG_READY → PRICE_QUOTED → SUBMITTING
→ QUEUED → RUNNING → POSTPROCESSING → SUCCEEDED | FAILED
```

账务独立：`NONE → QUOTED → AUTHORIZED → DEBITED | RELEASED | REFUNDED`。

### 失败回退

- URL/素材校验失败：修正输入，不重试任务。
- 提交响应未知：先按任务列表确认，不再次点击。
- 429：遵守 Retry-After，不创建新逻辑任务。
- provider/后处理失败：记录 attempt 与扣费；不假定失败会自动退款。
- CDN 下载失败：刷新媒体链接，不重新生成。

| S4 | 枚举目标受众、语言、风格和 TOP 7D/14D/28D 参考 | 默认值、候选视频、排序和选中态 | 每项配置含义明确 |
| S5 | 选择一个参考并冻结配置 | 参考指纹、结构摘要、quote、余额 | UI 明示 10 积分或实时报价 |
| S6 | 单次生成脚本 | job/request、状态、扣费、输出结构 | 一次提交、一份脚本、一笔净扣费 |
| S7 | 解析输出 | Hook、卖点顺序、口播、分镜、CTA、语言 | 输出字段完整且可编辑 |
| S8 | 编辑一处口播与一处镜头说明并刷新 | 持久化和版本变化 | 修改保存且不重新扣费 |
| S9 | 同商品只改变受众或语言生成第二份 | 配置敏感性和事实一致性 | 变化符合配置，商品事实不漂移 |

### 成本

- 官方当前公开价：每次脚本 10 积分。
- 基线加一次单变量对照：20 积分。
- 可选第三次完全重复输入用于估计随机性，需要另行批准 10 积分。

### 质量门槛

- 商品关键事实精确率 100%，不得虚构价格、功效、认证或使用场景。
- 输出至少包含 Hook、卖点顺序、口播和分镜。
- Hook 在脚本前两秒可执行；第一主卖点在五秒内出现。
- 语言配置必须覆盖全部用户可见脚本字段。
- 改变受众时，主卖点排序和措辞发生合理变化，商品事实保持不变。
- 参考结构相似但不复制连续长句；八个以上连续词相同触发人工审查。
- 用户编辑持久化，不因刷新或切换参考被静默覆盖。

### 状态机候选

```text
IDLE → RESOLVING_PRODUCT → PRODUCT_READY | NEEDS_MANUAL_INPUT
→ LOADING_REFERENCES → REFERENCES_READY
→ CONFIGURING → QUOTED → GENERATING
→ SCRIPT_READY | FAILED
SCRIPT_READY → EDITING → SAVED
```

### 失败回退

- 商品解析失败：转手动卖点或停止，不由模型猜测。
- 无同类爆款：记录是否回退到通用模板；不假定存在 RAG。
- 提交响应未知：先查任务队列和积分，不重复点击。
- 输出缺字段或事实错误：标记质量失败；不自动再次扣费。
